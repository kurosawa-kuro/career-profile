# 検討中事項

最終更新: 2026-07-06

## 1. 方針(確定)

**プログラマーから リーダー → PM → コンサル へシフトアップする。**

- 現案件(大手製造業 MLOps)で、顧客ヒアリング → 要件定義 → 資料化・スライド化 → プレゼン → PoC サンプル作成 → メンバーへのタスク分解 → レビュー、のサイクルを既に回している
- 支援組織の身内だけでなくクライアントからも高評価(「黒澤を外さないで」)。この実績が今後の最大の資産
- 45 歳・札幌・フルリモートの制約下では、実装スピードより顧客折衝・チーム推進側の方が賞味期限が長く単価も上がる

### ポジショニングの主張(確定)

経歴書・面談で以下を並行して強く主張する:

**主張 1: 肩書きは「リーダー」だが、提供価値の実質はコンサル領域である**

現案件のサイクルはコンサルの標準プロセスと一致している:

| 現案件で実施していること | コンサル工程 |
|---|---|
| 顧客ヒアリング | 課題発見・要求引き出し |
| 要件定義 | 課題の構造化・スコープ定義 |
| PoC サンプル作成 | 仮説検証 |
| 資料化・スライド化・プレゼン | 提言・合意形成 |
| タスク分解・メンバーへの配分・レビュー | デリバリー推進・品質担保 |

クライアント評価(「黒澤を外さないで」)は、コード品質ではなくこの上流工程への評価である点も根拠になる。

**主張 2: PM ノウハウとして欠けている要素は予算・人月(コスト見積・EVM 等)にほぼ限られ、他は実務経験済み**

| PM 知識領域 | 状況 |
|---|---|
| スコープ管理(要件定義・タスク分解) | ✅ 実務経験済み |
| ステークホルダー / コミュニケーション(ヒアリング・資料化・プレゼン) | ✅ 実務経験済み |
| 品質管理(レビューサイクル) | ✅ 実務経験済み |
| 資源管理(メンバーへのタスク配分) | ✅ 実務経験済み |
| スケジュール管理(サイクル運営) | ✅ 実務経験済み |
| **コスト管理(予算・人月見積・EVM)** | ❌ 未経験 — ギャップはここに限られる |
| 調達・契約管理 | △ 商流上ノータッチ(フリーランスの立場では通常触れない領域と説明可能) |

→ このギャップ整理は CAPM と噛み合う: **実務でカバー済みの領域は実績で主張し、欠けている予算・人月・予測型(EVM)は CAPM の学習でちょうど体系補完される**(CAPM 出題の暗記が必要な領域 = 予測型・EVM と一致)。「経験の証明は実務、欠落の補完は資格」という分担が成立する。

## 2. 資格・実績の優先順位(確定)

| 優先 | 項目 | 時期 | 位置づけ |
|---|---|---|---|
| 1 | **CAPM** | 2026 夏〜秋 | リーダー実務の浅さを履歴書上で補う「化粧」。PM トラックへの転換シグナル。**PMP への踏み台ではなく、それ自体を恒久の看板とする**(有効期間 3 年、更新は 15 PDU/サイクル — 更新計画込みで運用) |
| 2 | **Kaggle 銅** | 並行 | DS メンバーをレビューするリーダーとしての外形的証明(非 DL × Vertex 路線) |
| 3 | PMLE | 取り切れるなら | 「ついで」に降格。ただし現案件(GCP MLOps)が飯のタネである間は完全放棄しない |
| — | PMP | 前提としない | 監査(第三者署名)という自分でコントロールできない不確実性があるため、**取れない前提で計画を組む**。リーダー・PM・コンサルの証明は実務(クライアント評価・継続契約)でカバー。記録が貯まって取れるなら取る、程度の扱い |

### CAPM > Kaggle 銅 の論理(2026-07-06 確定)

1. **限界価値**: 履歴書の ML/エンジニア列には証拠が既に並んでいる(GCP 実案件・検証リポ・Qiita・AWS SAA)。Kaggle 銅はそこへの「追加の 1 本」。PM/コンサル列は外形的証明ゼロで、CAPM は「空の列に立つ最初の 1 本」— 転換期に書類で落ちる理由は PM 列の空白の方
2. **リスク構造**: CAPM は時間投下で結果が確定するタスク、Kaggle 銅は相手のいる確率的タスク(複数回挑戦の可能性)。must-have は確定的な方から確保する
3. **実務リターン**: CAPM の学習範囲(予算・人月・EVM)= 自認しているギャップそのもので、現案件のリーダー実務に即使え、最大の資産(クライアント評価)を強化する

**運用ルール**: Kaggle はコンペ日程という外部制約があるため「CAPM 後に着手」ではなく並行のバックグラウンド処理。ただし時間が競合したら CAPM が勝つ(優先度が高い = 先にやる、ではなく、競合時に勝つ)。

### PMLE 最下位の論理

PMLE は「これから離れる列(エンジニア)」を強化する資格で、3 つの中で学習量が最も重く、GCP パートナー要員としての価値も「エンジニアとして商流に乗る」場合にしか効かない。PM/コンサル転換の確定により最下位が論理的帰結(ユーザーの当初主張が正しかった)。

### ブロンズ戦略(判断の哲学)

「ゴールド級でないと資格として評価されない」は思い込み。書類選考・エージェント営業資料では資格は**有無でチェックされ、階級内の格付けまでは見られない**ことがほとんど。

→ ブロンズ級(CAPM / Kaggle 銅 / AWS SAA)を**最小コストで領域横断に並べ**、浮いた時間を実務に回す。ゴールド級 1 個より「PM もデータも基盤もわかるコンサル」という商品説明に合う。

## 3. CAPM 実行計画

1. **7 月中**: 受験資格の「PM 教育 23 時間」を充足(Udemy の PMP 35h コースで可。セール時数千円)
2. **申込**: PMI 会員登録してから申込(会員 $225 + 年会費 ≒ 非会員 $300 とほぼ同額で教材アクセス付き)
3. **8 月〜**: 学習着手。実務者の相場は 80〜120 時間
4. **10 月**: 受験

試験概要: 150 問・3 時間。出題比率は PM 基礎 36% / 予測型 17% / アジャイル 20% / ビジネスアナリシス 27%。
→ ビジネスアナリシス 27% は現案件の要件定義実務でほぼ貯金済み。暗記が必要なのは PMBOK 用語体系と予測型(EVM 等)。

取得後の経歴書表記: 「CAPM 取得(PMP は実務要件充足後に取得予定)」— 入門資格を「格下シグナル」でなく「PM トラックの現在地」として読ませる。
